# 上游倍率 / 余额变动提醒

本功能把「上游计费探测」已经读到的上游分组倍率和钱包余额持久化成历史，识别倍率变化与余额跌破阈值的时刻，并可通过账号运维（Account Ops）已配置的通知渠道发出提醒。

> 它**不会**额外请求上游：只观察上游计费探测每次写入的快照。所有开关默认关闭。

## 1. 前提

- 账号为 API Key 账号，并已在「编辑账号」中开启「上游计费自动探测」（倍率 / 余额数据来自探测快照）。
- 若需要推送通知，需在「账号运维」中配置至少一个通知渠道；否则事件会被记录为 `failed`。

## 2. 入口

后台侧边栏「上游变动」（`/admin/upstream-changes`）：

- **设置**：历史记录、倍率提醒、余额提醒、静音账号；
- **事件**：倍率变化与余额阈值穿越的列表，可按站点、类型、方向、账号筛选；
- **快照**：单账号最近 N 天的倍率 / 余额曲线数据。

## 3. 设置项（`settings` 表键 `upstream_change_alert_settings`）

| 字段 | 默认 | 说明 |
| --- | --- | --- |
| `record_history` | false | 每次成功探测写一条快照，并记录所有变化事件 |
| `retention_days` | 30 | 快照 / 事件保留天数（1–365），每小时最多清理一次 |
| `rate_alert_enabled` | false | 倍率变化提醒 |
| `rate_alert_direction` | `both` | `both` / `up` / `down`，按合并窗口内的**净变化**判断 |
| `rate_min_change_percent` | 0 | 相对变化小于该百分比时不提醒（事件仍记录），0–1000 |
| `merge_window_minutes` | 10 | 同一账号连续变化合并为一条通知的窗口（0–1440） |
| `cooldown_minutes` | 60 | 同一账号两次倍率通知的最小间隔（0–10080） |
| `balance_alert_enabled` | false | 余额跌破阈值提醒 |
| `balance_threshold` | 5 | 全局余额阈值（≥0），仅对没有单独余额规则的账号生效 |
| `balance_unit` | `USD` | 只有快照单位与此一致时才比较阈值 |
| `balance_cooldown_minutes` | 360 | 同一账号两次余额提醒的最小间隔（5–10080） |
| `muted_account_ids` | [] | 静音账号（最多 1000 个），事件记录为 `muted` |

只要「历史记录 / 倍率提醒 / 余额提醒」任一开启即生效；三者都关闭时完全不写库。

## 4. 判定规则

### 4.1 倍率变化

- 比较的是**实际计费倍率**：用户覆盖倍率优先，否则上游分组倍率；不含分时段峰值倍率。
- 新旧倍率都存在、本次探测的倍率是新鲜值、且差值超过 1e-9 时产生事件，方向为 `up` / `down`。
- 通知在后台周期内统一发送（见 4.3），同一账号在合并窗口内的多次变化合并成一条，消息展示“首个旧值 → 最新值”及变化次数；合并的旧事件标记为 `merged`。
- 净变化为 0、方向不匹配、相对变化低于阈值时分别记为 `suppressed` / `filtered`。

### 4.2 余额跌破阈值

- 余额由高于阈值变为 ≤ 阈值时记录 `low` 事件；由 ≤ 阈值回到阈值之上记录 `recovered` 事件（`recovered` 只记录不推送）。
- 账号运维中已为该账号设置单独余额规则时，本功能不重复提醒（`suppressed`），以账号运维的规则为准。
- 冷却期内的再次跌破记为 `suppressed`。

### 4.3 通知发送

- 上游计费探测服务每个周期先执行一次待发送事件的刷新，使用 leader 锁（`upstream:change:flush:leader`）保证多实例只有一个实例发送。
- 通知通过账号运维的广播接口发送到其已配置的渠道；没有可用渠道或发送失败记为 `failed`。

### 4.4 事件状态 `notify_state`

| 状态 | 含义 |
| --- | --- |
| `none` | 只记录，不需要通知（提醒开关关闭或 `recovered`） |
| `pending` | 等待下一次刷新 |
| `sent` / `failed` | 已发送 / 发送失败 |
| `muted` | 账号被静音 |
| `suppressed` | 被冷却、单独规则或净变化为 0 抑制 |
| `filtered` | 方向或最小变化百分比不满足 |
| `merged` | 合并到同窗口内最新一条事件的通知中 |

## 5. 数据表（迁移 `310_upstream_change_alerts.sql`）

- `upstream_rate_snapshots`：账号、站点、提供方、上游分组、分组倍率 / 解析倍率 / 实际倍率、余额与单位、观察时间。
- `upstream_change_events`：账号、账号名、站点、类型（`rate_multiplier` / `balance_low`）、方向、旧值 / 新值 / 阈值、单位、通知状态与时间。

站点键由账号 `base_url` 归一化得到（`scheme://host[:port][/path]`，去掉凭据、查询串与结尾的 `/v1`）。表中**不保存**任何凭据、密钥或令牌。账号删除时级联删除。

## 6. 管理接口

均位于 `/api/v1/admin`，需要管理员权限：

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET / PUT | `/upstream-changes/settings` | 读取 / 更新设置 |
| GET | `/upstream-changes/events` | 事件分页，参数 `site`、`kind`、`direction`、`account_id`、`page`、`page_size`（默认 50） |
| GET | `/upstream-changes/snapshots` | 单账号快照，参数 `account_id`（必填）、`days`（默认 7） |
| GET | `/upstream-changes/sites` | 已出现过的站点列表 |

## 7. 注意事项

- 本功能依赖探测快照的新鲜度：探测失败或未开启时不会产生事件。
- 首次开启时没有“上一次快照”，不会产生倍率事件；第二次成功探测后开始比较。
- 若同时使用账号运维的余额规则，建议只保留一种提醒方式，避免理解混乱（本功能已自动去重）。
